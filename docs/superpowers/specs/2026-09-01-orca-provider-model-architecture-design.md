# Orca 服务商与模型架构设计

## 目标

在 Orca Android 中建立参考 LobeHub 的服务商与模型架构：服务商独立注册、模型资料独立维护、请求运行时按协议复用，同时保留现有聊天、设置、模型分组和 API Key 加密能力。

## 范围

第一阶段固定纳入以下 22 个服务商入口，并按该顺序显示：

服务商列表是固定的初始目录；后续可以继续支持用户自定义服务商，但不扩大本阶段的内置目录。

## 架构

### 服务商目录

新增统一的服务商规格模型，每个内置服务商都有独立规格。规格包含：

- 稳定的 provider ID
- 显示名称和排序号
- 服务商分组显示名称
- API 协议类型
- 默认 API 地址
- API Key、OAuth 或本地连接认证方式
- 是否支持远程获取模型
- 默认测试模型
- 是否允许手动添加模型
- 能力和限制声明

斜杠名称在界面中作为一个服务商入口显示；如果底层认证或 API 协议不同，规格内部允许映射到不同的连接实现。

### 模型目录

每个服务商维护自己的模型目录。模型条目包含：

- 模型 ID 和显示名称
- 模型类型
- 模型家族和版本
- 上下文长度和最大输出长度
- 视觉、文件、函数调用、推理、搜索、音频、图片、视频等能力
- 发布日期和知识截止日期（如果来源提供）
- 价格信息（如果来源提供）
- 默认启用状态
- 模型专属参数和限制

模型来源分为内置、远程获取和用户自定义。远程模型刷新后写入现有模型缓存和数据库，不覆盖用户自定义模型。

### 运行时适配

运行时采用“服务商独立入口 + 协议级共享实现”：

- OpenAI 兼容服务商共用 Kotlin OpenAI-compatible adapter
- Anthropic 兼容服务商共用 Anthropic adapter
- Google Gemini 使用 Google 专用 adapter
- Ollama 使用本地 Ollama adapter
- Azure、Bedrock、GitHub Copilot、Coding Plan 等特殊认证或请求格式使用独立 adapter/规则
- Poolside、Inception 已核对官方 API，注册为 OpenAI 兼容服务商；StealthGPT 属于文本改写工具，不纳入普通模型服务商目录

每个服务商规格可以声明模型 ID 映射、请求参数转换、错误转换、模型列表转换和响应流转换规则。

### 数据流

```text
服务商目录
    ↓
服务商配置页
    ↓
ProviderRepository
    ├── 加密保存凭据
    ├── 保存服务商实例
    ├── 保存模型目录和启用状态
    └── 刷新远程模型
    ↓
ProviderFactory
    ↓
协议运行时适配器
    ↓
聊天请求和流式响应
```

聊天页只显示用户已经启用的模型，不新增独立的“模型中心”页面。模型仍在对应服务商详情页中管理。

## 界面

设置页面使用以下层级：

```text
设置
└── 服务商
    ├── 服务商列表
    └── 服务商详情
        ├── 配置
        └── 模型
```

配置页包含 API Key、代理地址、认证方式和连接测试。模型页包含获取模型、搜索、模型数量、启用/禁用、能力标签、上下文长度、排序和手动添加模型。

## 错误处理

- 未配置凭据时显示明确的配置提示，不发起空凭据请求。
- 模型获取失败时保留上次缓存，并显示刷新失败原因。
- 远程模型不得覆盖用户自定义模型。
- 不支持的协议或未核实的服务商显示“待配置”状态。
- 请求错误统一转换为 Orca 可读错误；协议特有错误保留服务商上下文。
- 不把 API Key 写入日志、模型列表或导出文件明文。

## 测试

需要覆盖：

- 22 个服务商的目录顺序和唯一 ID
- 服务商规格到协议适配器的映射
- 模型内置、远程和自定义来源的合并规则
- 模型启用/禁用和排序持久化
- 远程刷新不覆盖自定义模型
- API Key 加密保存和日志脱敏
- OpenAI 兼容、Anthropic、Gemini、Ollama 的请求和模型刷新
- 未配置或未核实服务商的安全失败路径
- 设置页返回路径和聊天页模型选择

## 许可证边界

只参考 LobeHub 的公开架构和服务商接入能力，用 Orca/Kotlin 重新实现；不复制 LobeHub 的 TypeScript 源文件、页面组件、Logo 或品牌资源。服务商 API 信息以各服务商官方文档为准，保留 Orca 及第三方依赖的许可证声明。
